# Qwen3 NPU Modeling 验证流程文档

## 概述

本文档详细说明如何从零开始验证 Qwen3 NPU modeling 的正确性，特别是针对已转换的 QNN 模型权重 `qwen3-1.7b-int8-rotated.mllm` 的 prefill 功能验证。

## 重要说明：运行环境架构

1. **主要开发服务器**（你的主要工作环境）
   - SSH: `root@10.29.230.87` (端口 6000)
   - **作用**：代码开发、编译、所有主要操作都在这里
   - **这是你当前 SSH 连接的地方，所有操作都在这个终端进行**

2. **Phoenix 服务器**（模型文件存储）
   - SSH: `XXX@10.109.246.210` (端口 20212)

   - **用途**：通过 SCP 从主要开发服务器获取模型文件，不需要直接登录操作

## 前置条件

### 1. 服务器信息

- **Phoenix 服务器**（开发环境）：

  - SSH 端口: `20212`

  - 密码: `xxx` (请替换为实际密码)
  - **用途**：代码编译、模型文件获取

### 2. Android 设备信息

- **设备连接**：通过 ADB 连接
- **示例设备**：`10.29.208.59:9808`（根据实际情况调整）
- **设备路径**：`/data/local/tmp/zl/mllm-v2/bin_PR/`（或你的部署目录）

### 3. 模型文件位置

- **Phoenix 服务器上的模型文件**：
  - 路径: `/data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm`
  - 配置文件: 需要从模型目录获取 `config.json`
  - Tokenizer 文件: 需要 `tokenizer.json`
- **需要推送到手机**：模型文件、配置文件、tokenizer 文件都需要通过 adb push 推送到手机

### 3. 模型特点

- **权重格式**: Linear 层权重为 `[out_dim, in_dim]` 格式，**未转置**
- **量化方式**: int8 量化，使用 W8A16 (weight int8, activation int16) 方案
- **特殊处理**: 需要在 `QNNLinearOp::load()` 中加载权重后调用 `tensor.transpose()` 进行转置

## 验证步骤

**重要**：以下所有步骤都在**主要开发服务器**上执行（你 SSH 连接到 `root@10.29.230.87` 的终端）。

### 步骤 1: 在主要开发服务器上检查环境

```bash
# 确保你在主要开发服务器上（root@10.29.230.87）
# 检查项目目录
cd ~/mllm_v2
ls -la

# 检查编译环境
python task.py --help  # 如果使用 task.py
# 或
cmake --version  # 如果使用 CMake
```

### 步骤 2: 从 Phoenix 服务器获取模型文件

**在主要开发服务器上，使用 SCP 从 Phoenix 获取模型文件**：

```bash
# 在主要开发服务器上执行
# 创建本地目录存储模型文件
mkdir -p ~/mllm_v2/test_qwen3

# 从 Phoenix 复制模型文件（首次需要输入密码）
scp -P 20212 XXX@10.109.246.210:/data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm \
    ~/mllm_v2/test_qwen3/qwen3-model.mllm

# 复制配置文件（如果有）
scp -P 20212 XXX@10.109.246.210:/data/shrelic/mllm_v2/config.json \
    ~/mllm_v2/test_qwen3/config.json

# 复制 tokenizer（如果有）
scp -P 20212 XXX@10.109.246.210:/data/shrelic/mllm_v2/tokenizer.json \
    ~/mllm_v2/test_qwen3/tokenizer.json
```

**提示**：
- 模型文件可能很大（几 GB），传输需要一些时间
- 可以使用 `rsync` 显示进度：`rsync -avz -e "ssh -p 20212" ...`
- 如果配置了 SSH 密钥，可以免密登录

### 步骤 3: 检查环境

```bash
# 检查磁盘空间
df -h

# 检查 conda 环境

# 检查 CUDA 环境（如需要）
nvidia-smi
```

### 步骤 4: 在主要开发服务器上编译代码

```bash

# 编译项目（根据你的构建方式选择）

ls -lh ~/mllm_v2/build-android-qnn-dbg/bin/mllm-qwen3-npu
```

### 步骤 5: 确认代码修改

#### 4.1 检查 QNNLinearOp 修改

确认 `mllm/backends/qnn/op/QNNLinearOp.cpp` 已包含权重转置逻辑：

```cpp
// 在 load() 方法中，对于 ModelFileVersion::kV1 和 kV2
weight_ = ploader->pull(getName() + ".weight");
if (weight_.shape().size() == 2) {
  // Transpose from [out_dim, in_dim] to [in_dim, out_dim]
  weight_ = weight_.transpose(0, 1);
}
weight_ = weight_.view({1, 1, options_.in_channels, options_.out_channels});
```

#### 4.2 检查 Qwen3 NPU 实现

确认以下文件存在且完整：
- `mllm/models/qwen3_npu/modeling_qwen3_npu.hpp`
- `mllm/models/qwen3_npu/configuration_qwen3_npu.hpp`
- `mllm/models/qwen3_npu/tokenization_qwen3_npu.hpp`
- `examples/qwen3_npu/main.cpp`

### 步骤 6: 在主要开发服务器上连接 Android 设备

### 步骤 7: 从主要开发服务器推送文件到 Android 设备

#### 7.1 推送可执行文件和库文件

**在主要开发服务器上执行**：

```bash

adb push ./libCustomPackageForHostTest.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libMllmCPUBackend.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libMllmRT.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./MllmFFIExtension.so /data/local/tmp/zl/mllm-v2/bin_PR/

# 或者一次性推送所有文件
adb push ./mllm-qwen3-npu ./libMllmQNNBackend.so ./libCustomPackageForHostTest.so \
        ./libMllmCPUBackend.so ./libMllmRT.so ./MllmFFIExtension.so \
        /data/local/tmp/zl/mllm-v2/bin_PR/
```

#### 7.2 推送模型文件

**在主要开发服务器上执行**（使用步骤 2 中获取的模型文件）：

```bash
# 推送模型文件到手机
adb push ~/mllm_v2/test_qwen3/qwen3-model.mllm \
    /data/local/tmp/zl/mllm-v2/bin_PR/qwen3-model.mllm

# 推送配置文件
adb push ~/mllm_v2/test_qwen3/config.json \
    /data/local/tmp/zl/mllm-v2/bin_PR/config.json

# 推送 tokenizer
adb push ~/mllm_v2/test_qwen3/tokenizer.json \
    /data/local/tmp/zl/mllm-v2/bin_PR/tokenizer.json
```

**注意**：
- 模型文件可能很大（几 GB），推送可能需要一些时间
- 如果文件已存在，可以跳过推送（检查文件是否存在）

### 步骤 8: 在 Android 设备上运行 Prefill 测试

**在主要开发服务器上执行**：

#### 8.1 进入设备 shell

```bash
# 在主要开发服务器上
adb shell
```

#### 8.2 在设备 shell 中设置环境并运行

```bash
# 进入部署目录
cd /data/local/tmp/zl/mllm-v2/bin_PR

# 设置库路径（重要！）

```

**注意**：
- 程序中的模型路径需要指向手机上的路径，例如：
  - 模型文件：`/data/local/tmp/zl/mllm-v2/bin_PR/qwen3-model.mllm`
  - 配置文件：`/data/local/tmp/zl/mllm-v2/bin_PR/config.json`
  - Tokenizer：`/data/local/tmp/zl/mllm-v2/bin_PR/tokenizer.json`
- 如果程序路径不对，需要修改 `examples/qwen3_npu/main.cpp` 中的路径

#### 8.3 检查输出

在 Android 设备的 shell 中观察以下内容：

1. **程序启动**：
   - 是否成功加载配置文件
   - 是否成功加载模型权重
   - 是否成功初始化 QNN backend

2. **Tokenizer 验证**：
   - 是否能正确 tokenize 输入文本
   - 输出 token IDs 是否合理

3. **Prefill 执行**：
   - 是否成功执行 prefill
   - 输出 logits 的 shape 是否正确
   - 是否有错误或警告信息

4. **KV Cache**：
   - KV cache 是否正确初始化
   - 是否按预期更新

**提示**：如果程序崩溃或出错，可以：
- 使用 `adb logcat` 查看系统日志
- 检查文件权限：`adb shell ls -l /data/local/tmp/zl/mllm-v2/bin_PR/`
- 确认所有依赖库都已推送

### 步骤 10: 调试技巧

#### 10.1 常见问题排查

1. **权重加载失败**：
   ```bash
   # 检查模型文件完整性
   file /data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm
   
   # 检查文件权限
   ls -l /data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm
   ```

2. **权重转置问题**：
   - 检查 `QNNLinearOp.cpp` 中的转置逻辑是否正确
   - 添加日志输出权重 shape，确认转置前后形状

3. **QNN backend 初始化失败**：
   - 检查 QNN SDK 是否正确安装
   - 检查环境变量设置
   - 查看日志中的错误信息

4. **内存不足**：
   ```bash
   # 检查可用内存
   free -h
   
   # 检查进程内存使用
   ps aux | grep mllm-qwen3-npu
   ```

#### 10.2 添加调试日志

在关键位置添加日志输出：

```cpp
// 在 QNNLinearOp::load() 中
MLLM_INFO("Loading weight: {}, shape before transpose: {}", 
          getName(), weight_.shape());
weight_ = weight_.transpose(0, 1);
MLLM_INFO("Weight shape after transpose: {}", weight_.shape());

// 在 prefill 执行前后
MLLM_INFO("Prefill input shape: {}", input.shape());
MLLM_INFO("Prefill output shape: {}", output.shape());
```

#### 10.3 使用 GDB 调试

```bash
# 编译时添加调试符号
cmake .. -DCMAKE_BUILD_TYPE=Debug

# 使用 GDB 运行
gdb ./mllm-qwen3-npu

# 在 GDB 中设置断点

(gdb) run
```

## 预期结果

1. **程序正常启动**：无崩溃，所有组件加载成功
