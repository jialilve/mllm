## 两种工作流程

### 方式 A: 在 Phoenix 上直接操作（推荐，更高效）

**优点**：
- ✅ 模型文件已经在 Phoenix 上，不需要传输
- ✅ 减少一次文件传输步骤
- ✅ 更直接高效

**前提条件**：
- Phoenix 服务器上需要安装 `adb` 工具
- Phoenix 服务器能够通过网络访问 Android 设备（`10.29.208.59:9808`）

#### 步骤 A1: 在 Phoenix 上编译代码（如果有编译环境）

```bash
# SSH 连接到 Phoenix
ssh -p 20212 zhu_lei@10.109.246.210

# 进入项目目录
cd /data/shrelic/mllm_v2

# 编译项目
python task.py tasks/build_android_qnn_debug.yaml
# 或
cd build-android-qnn-dbg
make -j$(nproc) mllm-qwen3-npu
```

**注意**：如果 Phoenix 上没有编译环境，可以在主要开发服务器上编译，然后通过 scp 将编译产物复制到 Phoenix。

#### 步骤 A2: 在 Phoenix 上连接 Android 设备

```bash
# 在 Phoenix 上检查 adb 是否可用
which adb
# 如果不存在，需要安装 Android SDK Platform Tools

# 连接 Android 设备
adb connect 10.29.208.59:9808

# 检查连接状态
adb devices
```

#### 步骤 A3: 在 Phoenix 上直接推送文件

```bash
# 在 Phoenix 上
cd /data/shrelic/mllm_v2/build-android-qnn-dbg/bin

# 推送可执行文件和库文件
adb push ./mllm-qwen3-npu /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libMllmQNNBackend.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libCustomPackageForHostTest.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libMllmCPUBackend.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./libMllmRT.so /data/local/tmp/zl/mllm-v2/bin_PR/
adb push ./MllmFFIExtension.so /data/local/tmp/zl/mllm-v2/bin_PR/

# 推送模型文件（模型文件已经在 Phoenix 上）
adb push /data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm \
    /data/local/tmp/zl/mllm-v2/bin_PR/qwen3-model.mllm

# 推送配置文件
adb push /data/shrelic/mllm_v2/config.json \
    /data/local/tmp/zl/mllm-v2/bin_PR/config.json

# 推送 tokenizer
adb push /data/shrelic/mllm_v2/tokenizer.json \
    /data/local/tmp/zl/mllm-v2/bin_PR/tokenizer.json
```

#### 步骤 A4: 在 Android 设备上运行

```bash
# 在 Phoenix 上通过 adb shell 进入设备
adb shell

# 在设备 shell 中
cd /data/local/tmp/zl/mllm-v2/bin_PR
export LD_LIBRARY_PATH=.
./mllm-qwen3-npu
```

## 推荐方式

**优先尝试方式 A（在 Phoenix 上直接操作）**，因为：
1. 模型文件已经在 Phoenix 上，不需要额外传输
2. 减少文件传输步骤，更高效
3. 操作更直接

**如果方式 A 不可行**（网络不通或没有 adb），再使用方式 B。

## 关键点总结

### 在哪里操作？

**所有操作都在主要开发服务器上**（你 SSH 连接到 `root@10.29.230.87` 的终端）：

1. ✅ **编译代码** - 在主要开发服务器
2. ✅ **获取模型文件** - 从主要开发服务器通过 SCP 从 Phoenix 获取
3. ✅ **推送文件** - 从主要开发服务器通过 ADB 推送到手机
4. ✅ **运行测试** - 通过 ADB shell 在手机上运行

### 不需要的操作

- ❌ **不需要**在 Windows 上单独开终端连接 Phoenix
- ❌ **不需要**在 Phoenix 上直接操作（除非需要检查文件）
- ❌ **不需要**在手机上手动操作（通过 ADB 即可）

## 简化工作流程脚本

可以在主要开发服务器上创建一个脚本 `~/mllm_v2/scripts/push_qwen3_npu.sh`：

```bash
#!/bin/bash

# 配置
PHOENIX_USER="XXX"
PHOENIX_HOST="10.109.246.210"
PHOENIX_PORT="20212"
PHOENIX_MODEL_PATH="/data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm"
ANDROID_DEVICE="10.29.208.59:9808"
ANDROID_DEST="/data/local/tmp/zl/mllm-v2/bin_PR"
LOCAL_MODEL_DIR="~/mllm_v2/test_qwen3"

# 1. 从 Phoenix 获取模型文件（如果不存在）
if [ ! -f "$LOCAL_MODEL_DIR/qwen3-model.mllm" ]; then
    echo "从 Phoenix 获取模型文件..."
    mkdir -p $LOCAL_MODEL_DIR
    scp -P $PHOENIX_PORT $PHOENIX_USER@$PHOENIX_HOST:$PHOENIX_MODEL_PATH \
        $LOCAL_MODEL_DIR/qwen3-model.mllm
fi

# 2. 连接 Android 设备
echo "连接 Android 设备..."
adb connect $ANDROID_DEVICE

# 3. 推送可执行文件和库
echo "推送可执行文件和库..."
cd ~/mllm_v2/build-android-qnn-dbg/bin
adb push ./mllm-qwen3-npu ./libMllmQNNBackend.so \
    ./libCustomPackageForHostTest.so ./libMllmCPUBackend.so \
    ./libMllmRT.so ./MllmFFIExtension.so $ANDROID_DEST/

# 4. 推送模型文件
echo "推送模型文件..."
adb push $LOCAL_MODEL_DIR/qwen3-model.mllm $ANDROID_DEST/

echo "完成！现在可以运行: adb shell 'cd $ANDROID_DEST && LD_LIBRARY_PATH=. ./mllm-qwen3-npu'"
```

## 常见问题

### Q: 我应该在哪个终端操作？

**A**: 在你 SSH 连接到主要开发服务器（`root@10.29.230.87`）的终端中操作。不需要在 Windows 上开新终端。

### Q: 如何从主要开发服务器访问 Phoenix？

**A**: 使用 SCP 或 SSH 命令，例如：
```bash
# 检查 Phoenix 上的文件
ssh -p 20212 XXX@10.109.246.210 "ls -lh /data/shrelic/mllm_v2/"

# 复制文件
scp -P 20212 XXX@10.109.246.210:/path/to/file ./local/path
```

### Q: 模型文件很大，传输很慢怎么办？

**A**: 
- 使用 `rsync` 可以显示进度和断点续传
- 或者配置 SSH 密钥免密登录，使用压缩传输：`scp -C -P 20212 ...`

### Q: 每次都要重新获取模型文件吗？

**A**: 不需要。模型文件通常不会变化，只需要：
- 首次获取一次
- 如果模型文件更新了，再重新获取
- 每次编译后只需要推送可执行文件和库文件
