# Qwen3 NPU 验证环境说明

## 环境架构概览

### 开发环境：Phoenix 服务器

**Phoenix 是什么？**
- Phoenix 是一个 **GPU 服务器**，用于开发和编译
- 配置：8块 A40 42G GPU，64核 CPU，500G 内存
- IP: `10.109.246.210`，SSH 端口: `20212`

**Phoenix 的作用**：
1. ✅ **代码开发**：编写和修改代码
2. ✅ **代码编译**：编译 Android 版本的可执行文件
3. ✅ **模型存储**：存储模型文件（如 `qwen3-1.7b-int8-rotated.mllm`）
4. ✅ **模型转换**：进行模型格式转换等需要 GPU 的任务
5. ❌ **不用于实际推理**：QNN 推理必须在 Android 设备上运行

### 运行环境：Android 手机

**Android 设备的作用**：
- 实际执行 QNN 推理
- 运行编译好的可执行文件
- 通过 ADB 连接进行文件传输和远程执行

**为什么要在手机上运行？**
- QNN (Qualcomm Neural Network) SDK 是专门为 Qualcomm 芯片的 NPU 设计的
- NPU 推理必须在支持 QNN 的 Android 设备上运行
- 服务器上的 CPU/GPU 无法直接运行 QNN 推理

## 关键步骤说明

### 步骤 1: 在 Phoenix 上获取模型文件

```bash
# 连接到 Phoenix
ssh -p 20212 XXX@10.109.246.210

# 检查模型文件
ls -lh /data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm
```

### 步骤 2: 在 Phoenix 上编译代码

```bash
cd /data/shrelic/mllm_v2
cd build-android-qnn-dbg
make -j$(nproc) mllm-qwen3-npu
```

### 步骤 3: 从 Phoenix 推送文件到手机

```bash
# 连接手机
adb connect 10.29.208.59:9808

# 推送可执行文件和库
cd /data/shrelic/mllm_v2/build-android-qnn-dbg/bin
adb push ./mllm-qwen3-npu ./lib*.so /data/local/tmp/zl/mllm-v2/bin_PR/

# 推送模型文件
adb push /data/shrelic/mllm_v2/qwen3-1.7b-int8-rotated.mllm \
        /data/local/tmp/zl/mllm-v2/bin_PR/qwen3-model.mllm
```

### 步骤 4: 在手机上运行

```bash
adb shell
cd /data/local/tmp/zl/mllm-v2/bin_PR
LD_LIBRARY_PATH=. ./mllm-qwen3-npu
```

## 常见问题

### Q1: 为什么不能在 Phoenix 上直接运行？

**A**: QNN SDK 是专门为 Qualcomm 芯片的 NPU 设计的，只能在支持 QNN 的 Android 设备上运行。Phoenix 服务器上的 CPU/GPU 无法直接运行 QNN 推理。

### Q2: 模型文件很大，推送很慢怎么办？

**A**: 
- 模型文件通常几 GB，首次推送可能需要一些时间
- 可以使用 `adb push` 的进度显示查看推送状态
- 如果文件已存在，可以跳过推送（检查文件是否存在）

### Q3: 每次修改代码后都需要重新推送吗？

**A**: 
- 是的，每次编译后需要推送新的可执行文件和库文件
- 模型文件通常不需要重复推送（除非模型文件本身有更新）

### Q4: 如何知道文件是否推送成功？

**A**: 
```bash
# 检查文件是否存在
adb shell ls -lh /data/local/tmp/zl/mllm-v2/bin_PR/

# 检查文件大小
adb shell du -h /data/local/tmp/zl/mllm-v2/bin_PR/qwen3-model.mllm
```

## 总结

- **Phoenix 服务器** = 开发环境（编译代码、存储模型）
- **Android 手机** = 运行环境（执行 QNN 推理）
- **工作流程** = 在 Phoenix 编译 → 通过 ADB 推送 → 在手机上运行
